# 만약 당신이 범죄자라면… · 저택 데모

첨부 타이틀 이미지와 저택 도면을 사용한 pico2d 잠입·퍼즐 데모입니다.
현관, 연회장, 주방, 복도, 서재, 금고실과 사용인 복도·경비 구역·보안실의 총 9개 방을 각각 한 화면에 표시합니다.
목적지가 써 있는 문 쪽으로 걸어가면 화면이 전환됩니다. 각 방의 벽과 주요 가구에는 이동 충돌을 적용했습니다.

## Windows에서 실행

Python 3.10 이상을 권장합니다. 압축을 푼 뒤 `main.py`가 있는 폴더에서 명령 프롬프트를 열고 다음을 실행합니다.

```bat
py -m pip install -r requirements.txt
py main.py
```

한글 표시에는 시스템의 맑은 고딕 또는 굴림을 사용합니다. Linux는 나눔고딕 또는 Noto Sans CJK를 지원합니다.

## 조작

| 키 | 기능 |
|---|---|
| Space / Enter | 타이틀에서 시작 |
| WASD / 방향키 | 걷기와 문 통과 |
| E | 가까운 대상과 대화·조사 또는 물건 줍기 |
| Q | 든 물건 내려놓기 |
| 마우스 왼쪽 클릭 / 숫자키 / Enter | 금고 키패드 입력과 확인 |
| Esc | 암호 입력 취소 또는 게임 종료 |
| R | 결과 화면에서 다시 시작 |

보석을 확보한 뒤 현관의 ‘저택 밖’ 출구로 나가는 것이 목표입니다.
저택에 남은 여러 기록을 연결해 금고를 여는 루트와, 세 NPC 관련 사전 준비를 마친 후
주인을 협박하는 루트가 있습니다. 금고 암호와 대사는 데모 설정입니다.
보안 전문가가 보안을 점검할 때는 금고실 출입으로 의심도가 오르지 않습니다.
칼이나 보석을 목격하면 기존처럼 의심도가 오릅니다.

## 코드

- `rooms.py`: 방별 이미지 좌표와 벽·가구·문 영역
- `stage.py`: 충돌, 문 전환, 목격과 강도 결과 판정
- `play_mode.py`: 방별 캐릭터와 상호작용, HUD, 탈출
- `game_world.py`, `game_framework.py`: 객체 갱신과 게임 모드 전환

`python tests/headless_verify.py`로 스프라이트와 기본 게임 로직을 점검할 수 있습니다.


## 현장 조사 자료와 사건 이후 현장

종이 묶음을 E로 주우면 자료 1개씩, 총 3개를 얻습니다.
모든 방에서 H를 눌러 사건 이후 현장을 조사할 수 있습니다. 처음 여는 방에서는 자료 1개를 사용하며,
이미 연 방은 무료로 다시 볼 수 있습니다. 어느 방을 먼저 조사할지 직접 선택합니다.
흔적은 당시의 작은 변화나 증언으로 제시하며, 힌트 위치 목록은 미리 안내하지 않습니다.

조사 중에는 재현의 NPC와 의심도 타이머가 멈춥니다.
E로 흔적을 조사하고 H 또는 Esc로 복귀합니다. N으로 수첩을 열어 방향키로 기록을 넘깁니다.
다시 시작하면 자료와 수첩도 초기화됩니다.

사진작가는 대화 후 촬영을 멈추고 서재에서 45초 동안 장비를 점검한 뒤 연회장으로 돌아옵니다.

## 방 배치

연회장의 식탁과 의자는 원래 크기의 78%로 함께 표시하고 충돌도 같은 비율로 적용합니다.
보안 전문가 이도현은 보안실과 금고실 앞 경비 구역을 오갑니다.
주방 조리대 위의 칼, 서재 책상 위의 수면제, 연회장 음료대 위의 커피는
가구 옆으로 접근한 뒤 E로 집습니다.

## 선수의 감시 멈추기

연회장의 커피와 서재의 수면제를 찾습니다. 한쪽을 E로 든 상태에서
다른 쪽에 접근해 E를 누르면 수면제가 든 커피로 조합됩니다.
획득 순서는 자유롭습니다. 복도의 선수에게 E로 건네면 잠들고 감시와 강도 개입이 멈춥니다.
프로틴, 일반 커피, 수면제 단독으로는 선수를 무력화할 수 없습니다.
조합한 커피도 Q로 내려놓고 E로 다시 주울 수 있습니다.


## 화자별 대화 스크립트

시작하면 집주인이 파티와 금고실의 보석을 소개합니다.
선수와 보안 전문가의 대화, 복도 현장 조사 시 선수 증언도 대화창으로 표시됩니다.
Enter, Space 또는 E로 한 장씩 넘깁니다. 대화 중에는 이동과 NPC 갱신, 의심도 타이머가 멈춥니다.
대사 원문은 dialogue.py에서 수정할 수 있습니다.
일반 커피를 선수에게 건네도 잠들지는 않습니다. 주방의 요리사에게 빈손으로 말을 걸면 새 커피를 받을 수 있습니다.


## 시작 설정과 준비 시간

시작 화면에서 위·아래 방향키로 난이도 또는 준비 시간을 선택하고
왼쪽·오른쪽 방향키로 변경합니다. 노멀은 180초, 하드는 60초를 기본값으로 합니다.
난이도를 바꾸면 준비 시간도 해당 기본값으로 돌아갑니다.
준비 시간은 30~300초 범위에서 15초 단위로 별도 조정할 수 있습니다.

Enter 또는 Space로 탐정 브리핑을 시작합니다. 준비 타이머는 브리핑과 집주인 환영 대사가
끝나고 직접 움직일 수 있을 때부터 줄어듭니다. 대화, 현장 조사, 수첩, 암호 입력 중에는 멈춥니다.
주인을 칼로 협박하거나 올바른 금고 암호를 입력하면 준비가 조기에 종료됩니다.

시간이 끝나면 추가 도구 획득·조합, 음료 제공, 경보 해제, 사진작가 이동을 할 수 없습니다.
확보한 칼로 주인을 협박하거나 금고 암호를 입력해 범행을 진행할 수 있습니다.
시간 만료 자체로 게임이 끝나지는 않습니다. 결과 화면의 R은 같은 설정으로 새 게임을 시작합니다.
현재 노멀·하드의 차이는 준비 시간 기본값입니다.


## 강도 루트와 추적 탈출

집주인 김재현은 금고실에 있습니다. 준비 시간 안에 선수를 재우고 경보를 점검 모드로 바꾸고
사진작가를 장비 점검하러 보내야 합니다. 칼을 확보한 뒤 금고실의 집주인에게 E로 협박합니다.
현재 협박 시 세 준비 조건을 검사하며, 빠진 항목이 있으면 기존처럼 실패합니다.

강도로 금고를 연 뒤 보석을 얻으면 각 방에 흩어져 있던 보안 전문가·총무·사진작가가 추적을 시작합니다.
발소리 안내 후 1.5초의 반응 시간이 있으며, 추적자는 가구와 벽을 피해 문을 통해 방을 건너옵니다.
가까이 붙잡히기 전에 복도, 연회장, 현관을 거쳐 탈출해야 합니다.
보석을 내려놓아도 추적은 끝나지 않습니다. 대화·수첩·현장 조사 중에는 추적도 멈춥니다.
암호로 조용히 금고를 연 경우에는 추적이 시작되지 않고 기존 순찰과 목격 규칙을 유지합니다.
결과 화면은 탐정 윤시현이 범행 과정이나 재현의 문제점을 말하는 형식이며 R로 다시 시작할 수 있습니다.


## 잠입 동선과 순찰

- 짧은 길: 연회장 → 복도 → 경비 구역 → 금고실
- 우회로: 주방 ↔ 사용인 복도 ↔ 서재 ↔ 복도
- 경비 구역 위쪽 문으로 보안실에 들어갑니다. 기둥과 장식장은 이동과 시야를 모두 막습니다.
- 선수는 복도와 현관, 요리사는 주방과 연회장, 총무는 연회장과 서재를 오갑니다.
- 보안 전문가는 보안실과 경비 구역을 순찰하고, 사진작가는 연회장 내 여러 지점에서 멈춰 주변을 봅니다.
- NPC는 가구를 돌아 문으로 방을 이동하고, 각 지점에서 잠시 멈춰 시선을 바꿉니다.

## 감시 카메라와 별도 점검

복도와 경비 구역에는 회전하는 카메라가 있습니다. 바닥의 점선은 현재 시야이며,
가구 뒤에서는 감지되지 않습니다. 일반 손님이 빈손으로 복도를 다니는 것은 의심 행동이 아닙니다.
칼·보석 소지 또는 출입 제한 구역에 있는 모습이 1초 동안 보이면 의심도가 1 오릅니다.
경고 중 시야를 벗어나면 감지가 초기화되고, 계속 보이면 2.5초 보호 시간이 지난 뒤 다시 누적됩니다.

보안 전문가와 대화하면 **금고 경보만** 점검 모드가 됩니다.
보안실의 카메라 점검 단말에 E로 접근하면 준비 시간 중 **카메라만 45초간** 정지합니다.
남은 시간은 화면에 표시되며, 시간이 지나면 다시 감시합니다. 두 점검은 독립적입니다.
대화·현장 조사·수첩·암호 입력 중에는 순찰, 회전, 감지, 점검 시간 모두 멈춥니다.
새 방에도 조사 흔적을 추가했으며 자료는 기존처럼 총 3개입니다.

`python tests/headless_verify.py`는 9개 방의 문 연결·우회로, 순찰의 가구 회피,
카메라 예고와 가림·누적·정지, NPC 분산 후의 강도 추적과 암호 루트도 검사합니다.


## 설명문과 힌트 구분

일반 획득·조합 메시지는 행동의 결과만 알립니다. 조합 직후 사용 대상이나 다음 해결 행동을
지시하지 않으며, 접근 시 표시하는 문구도 도구의 용도나 조합법을 미리 제시하지 않습니다.
NPC 자신의 요구와 상황을 말하는 대사, 조작 안내, 실제 사용 후 나타나는 결과는 유지합니다.
물건의 용도와 사건 흔적을 연결하는 추론은 H 현장 조사와 그 내용을 기록한 N 수첩에서 확인합니다.


## NPC 행동 트리 (LEC18)

`py_trees`의 Selector·Sequence·Blackboard로 NPC 판단을 구성합니다.
수면/비활성 → 강도 추적 → 순찰 → 기본 이동 순으로 선택하며, 추적은 매 tick 조건을 재검사하고
순찰은 중단돼도 가던 지점부터 재개합니다.
추적 시작 조건과 이동 속도, 방 사이 경로 탐색, 카메라 규칙은 유지합니다.
업데이트 후 `py -m pip install -r requirements.txt`를 한 번 실행하세요.
트리 도식과 캐릭터별 배정, 강의 페이지 대응은 [NPC 행동 트리 설명](docs/NPC_BEHAVIOR_TREES.md)에 있습니다.


## 일반 기록을 연결하는 암호 퍼즐

총무는 개관 행사에 관한 배경만 이야기하며 날짜나 금고 번호의 관계를 알려주지 않습니다.
일반 기록은 H 자료와 별개로 E로 읽고, N 수첩의 ‘일반 기록’에 저장합니다.
빈손일 필요가 없고 자료를 소비하지 않습니다. 종이는 남아 있어 다시 읽을 수 있습니다.
읽는 대화 중에는 기존처럼 준비 시간과 NPC·카메라가 멈춥니다.

| 일반 기록 | 조사 방식 | 알 수 있는 내용 |
|---|---|---|
| 금고 명판 | 닫힌 금고를 처음 E로 조사 | ‘이 집이 처음 손님을 맞은 날을 기억하며.’와 월/일 표시 |
| 개관 행사 준비표 | 사용인 복도의 장식장에 놓인 문서에 E | 개관 행사 개최 월 |
| 최초 행사 출입 기록 | 보안실 책상에 놓인 문서에 E | 같은 개관 행사의 방문객 출입 개시 일 |

두 문서에 공통 행사명과 월계수 표식이 있어 같은 행사인지 대조할 수 있습니다.
단일 문서는 전체 암호를 알려주지 않습니다. 금고에서는 월 두 자리 / 일 두 자리를 수동 입력합니다.
이미 답을 아는 플레이어의 입력을 막는 수집 개수 제한이나 자동 입력은 추가하지 않았습니다.

H 현장 조사는 같은 행사 기록의 연결과 명판 의미를 이해하는 추가 힌트입니다.
H를 사용하지 않아도 일반 기록만으로 풀 수 있고, 현장 조사 내용은 수첩에 별도로 유지됩니다.
일반 기록은 준비 시간이 끝나도 읽을 수 있으며 재시작 시 수집 상태가 초기화됩니다.
기존 강도 루트, 추적, 암호 루트 성공/실패 조건은 유지합니다.


## 클릭형 금고 키패드

금고를 E로 조사하고 명판 대사를 넘기면 월/일 네 자리와 숫자 버튼이 있는 키패드가 열립니다.
숫자를 마우스 왼쪽 버튼으로 클릭하고 ‘확인’을 누르면 됩니다. ‘지우기’는 마지막 한 자리를,
‘닫기’는 입력을 취소합니다. 마우스를 올린 버튼은 밝게 표시됩니다.
기존 숫자키·Backspace·Enter/Space·Esc 입력도 동일하게 동작하며 클릭과 섞어서 쓸 수 있습니다.
네 자리보다 적게 입력하면 확인하지 않고 안내하며, 오답은 창을 유지한 채 입력만 비워 다시 시도할 수 있습니다.
키패드를 사용하는 동안 준비 시간·NPC·감시 카메라는 기존 암호 입력과 같이 멈춥니다.


## 사용인 복도 발견과 감시

사용인 복도는 주방의 차와 식기를 서재로 운반하던 뒤편 동선입니다.
처음에는 주방에 ‘작업용 문’, 서재에 ‘보조문’만 표시하고 연결 목적지는 숨깁니다.
문은 처음에 닫혀 있으므로 방향키로 밀고 지나가는 것만으로는 전환되지 않습니다.
다음 중 하나로 발견하면 두 문이 열리고 연결 이름이 표시됩니다.

- 주방 조리대의 ‘배식 동선 메모’를 E로 읽는다. 기록은 수첩에 남으며 H 자료를 소비하지 않는다.
- 작업문이나 보조문 가까이에서 E로 조사한다. 수레 흔적과 안쪽 복도, 카메라에 관한 대사를 확인한다.

복도 안은 식기 선반이 엇갈리게 배치되어 직선으로 통과할 수 없습니다.
선반은 이동과 카메라 시야를 함께 막으며, 회전 카메라 한 대가 사용인 전용 구역을 감시합니다.
따라서 빈손이어도 시야에 1초 이상 머무르면 의심도가 오릅니다.
경고 중 벗어나거나 선반 뒤에서 기다릴 수 있고, 보안실 단말의 45초 정지는 이 카메라에도 적용됩니다.

NPC는 원래 이 동선을 알고 있으므로 플레이어의 발견 상태와 무관하게 추적에 이용합니다.
주방 → 사용인 복도 → 서재로 이어지는 문 방향은 유지해 입력을 계속 눌러도 되돌아오지 않습니다.
재시작하면 발견 상태도 초기화됩니다. 암호에 필요한 월 기록은 복도 안에 유지했습니다.


## 문 표시와 통과 범위

모든 방 연결을 같은 층의 출입문으로 표시합니다. 계단처럼 보이던 문턱·가로 막대 도형은 제거했습니다.
정면 출입구는 제공된 저택 에셋의 갈색 문을 바탕으로 분리한 이미지를 사용하고,
좌우 벽에는 같은 목재색의 측면 문 이미지를 사용합니다. 왼쪽 벽에서는 좌우 대칭으로 그립니다.
위아래 연결도 이미지를 회전시키지 않고 수직으로 세웁니다.
사용인 복도를 발견하기 전의 작업문은 닫힌 측면 문이며, E 조사나 배식 메모로 발견하면 열립니다.

`door_art.py`가 방향별 이미지·발 위치·크기·이름표 높이를 결정합니다.
이미지 원본과 투명 영역 제외 클립 좌표는 `assets/doors/`와 `manifest.json`에 있습니다.
이미지 출처 및 생성 요청은 같은 폴더의 `source.json`에 기록했습니다.
그림 교체는 기존 방 연결이나 충돌 판정을 변경하지 않습니다.
연회장↔주방 문의 통과 반폭은 양쪽 모두 원본 좌표 36픽셀입니다.
중앙뿐 아니라 위·아래 가장자리에서의 실제 Player.update 이동과 문 바깥 벽 차단을 검사합니다.
